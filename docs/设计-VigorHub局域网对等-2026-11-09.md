# 设计：VigorHub 局域网对等（被发现 / 被拉取半边）

日期：2026-11-09
涉及文件：`src/vigorhubpeer.h/.cpp`（新增）、`src/vigorhubrelay.h/.cpp`、`src/appsettings.h/.cpp`、
`src/vigorhubpage.h/.cpp`、`CMakeLists.txt`、`justfile`、`tools/vigorhubpeer_selftest.cpp`（新增）
对端仓库：`vigorhub`（`src/lan.rs`、`src/model.rs`、`src/ui/app.rs`）

## 原来缺什么

本应用只有推送半边：`VigorHubRelay` 把聚合结果 `POST` 到
`http://<桌面>:18765/api/health-motion/v1/push`。没有伴随 HTTP 服务、没有组播宣告、
没有设备身份（alias / device_type / fingerprint 一个都没有）。

后果是 AW 数据能不能过去，完全取决于那个手填地址推没推成功：

- 桌面端的「已发现设备」列表里看不到本机；
- 桌面端顶栏「立即同步」和后台每 60 秒的自动拉取都绕过本机；
- 推送失败时没有第二条路兜底。

手环保姆那边两条半边都有（`LanRelayTransport` 推 + `LanRelayServer` 被发现/被拉），
本次把本应用补齐到对称。

## 补了什么

`VigorHubPeer`（常驻，随 `VigorHubRelay` 起停）：

1. `QTcpServer` 监听 `QHostAddress::Any`、端口 `0`（系统分配），暴露
   - `GET /api/health-motion/v1/info` → 平铺 `DeviceInfo`
   - `GET /api/health-motion/v1/snapshot` → `{"aw":{"app_usage":[...],"cursors":[...]}}`
   - 其余路径 → `{"app":"aw-qtui"}`；非 GET → 405
2. `QUdpSocket` 每 2 秒往 `224.0.0.167:53317` 宣告自身（与桌面端 `lan.rs` 的
   `MULTICAST_ADDR` / `MULTICAST_PORT` 对齐，LocalSend 同款组播组）。
3. 稳定身份：指纹按「主机名 + 用户名」FNV-1a 64 派生，32 位小写十六进制，跨重启不变。

`/snapshot` 报的是**已持久化累计表的全量**（`m_totals` 全部天 + `m_cursors`），
不是本轮增量：桌面端可能在任何时刻来拉，只报增量会让它那边缺掉之前推过的天。
推送侧发「本轮触碰的天」，两者共用 `usageRows()` 一份口径，不会各算一套。
桌面端按 `(day, source, app)` 全量替换合并（`model.rs::merge_usage_full`），所以重复拉取幂等。

## 两条必须守住的协议约束

### device_type 必须是 `aw`，不能是 `desktop`

桌面端 `lan.rs::peer_from_announce` 会把 `device_type == "desktop"` 的宣告整条丢掉。
这不是疏漏：另一台健康运动 hub 的 `/snapshot` 明确回
`{"ok":false,"error":"snapshot not provided by desktop"}`，互拉只会每 60 秒刷一条失败日志。

`aw` 是真的提供快照的**数据源**，和 `phone` 同类，所以放行。桌面端那边把取值注释从
`"desktop" | "phone"` 扩到 `"desktop" | "phone" | "aw"`，并给设备列表加了人话标签
（手机 / 电脑使用 / 健康运动）。

手机端的 `LanRelayTransport.multicastScan` 只认 `device_type == "desktop"`，
所以它不会把本应用误当成中转目标——手环数据不会推到 AW 对等体上来。

### 指纹命名空间必须和 hub 不同

本应用常常就跑在桌面端**同一台机器同一个用户**下。那时源 IP 也是 `127.0.0.1`，
唯一能把两者分开的是指纹。桌面端用 `health-motion|{COMPUTERNAME}|{USERNAME}` 派生，
本应用必须用 `aw-qtui|{COMPUTERNAME}|{USERNAME}`。前缀若相同，两个指纹相等，
hub 会把本机 AW 当成自己的组播环回丢掉，「本机 ActivityWatch 数据同步过去」
这条路直接断在发现阶段。

这条契约两端各钉一道门：

- 桌面端 `lan::tests::aw_fingerprint_namespace_differs_from_hub`：断言自己的指纹等于
  `health-motion|` 口径，且换成 `aw-qtui|` 口径必须得到不同值。
- 本应用 `tools/vigorhubpeer_selftest.cpp`：独立算一遍 hub 口径，断言
  `VigorHubPeer::fingerprint() != hubStyleFingerprint()`。

## 本机传输也走局域网那套代码

用户明确提到「有可能是在本机内进行传输的，但代码要写成像局域网内一样的功能，
后续局域网内估计会添加其他的主机」。实现里因此没有任何一处把目标写死成回环：

- 监听 `Any` 而不是 `LocalHost`，端口由系统分配后如实报进 `/info` 与宣告；
- 组播出口显式钉到默认路由网卡（`outboundInterface()`，用「连 8.8.8.8 选路」拿本机出站
  IPv4 再匹配网卡）。多网卡机器上 WSL / VMware / VPN 各挂一张虚拟网卡，不钉住就会把
  宣告发到一张根本不通局域网的口上——桌面端 `lan.rs::bind_multicast_socket` 同样为此
  显式设了 `IP_MULTICAST_IF`；
- 推送目标地址仍然可配（默认 `127.0.0.1:18765`），但**伴随服务不读它**：关掉自动推送
  （间隔设「仅手动」）时桌面端照样能发现并来拉。

自测里证明这件事的硬门是 `peer.bindAddress() == QHostAddress::Any`：读 `listen()` 之后的
真实 socket 状态，不受防火墙影响。若实现偷偷只绑了 `LocalHost`，这条会红（mutant 臂验过）。

**原来那条「进程内连本机非回环 IPv4 也要 200」的门被降级成 `[INFO]` 诊断了**，因为它量不准：
自测进程连本机自己的 WLAN IPv4 会 5 秒超时（`state=0`），虚拟网卡那条也一样，但**跨进程**
的真实 hub 从同一个地址拉得到——它自己的持久日志里就有 `已合并来自 pull:192.168.88.246`。
防火墙查不出所以然（WLAN 是 Public，但已有两条针对该 exe 路径的 Enabled Inbound Allow 规则，
hub 在同一地址上 curl 也通）。所以判「是不是 localhost-only」用绑定地址，不用这条会被环境
干扰的探测。探测本身另配 control 自证：再起一个**只绑 `LocalHost`** 的 `QTcpServer`，
用同一个 `httpRoundTrip` 从回环打它必须 200，并断言它的 `serverAddress()` 真的是 `LocalHost`；
这三条 control 红了才说明是夹具坏了而不是网络坏了。

## 多台 AW 主机：来源标识

桌面端按 `(day, source, app)` 整条替换。原来 `source` 硬编 `"desktop"`，
局域网里第二台 AW 主机推过来会把第一台的时长**覆盖**掉。

新增配置项 `vigorhub/sourceLabel`（界面「来源标识」，留空 = `desktop`）：

- 本机留空，保持存量数据的键不断（否则旧行 `desktop` 与新行并存，同一天时长被算两遍）；
- 其它每台 AW 主机填一个不同值（主机名最省事）。

界面上把这个后果写成了提示，不用翻文档才知道要填。

## 起停与配置

- 伴随服务只跟**总开关**走，不跟推送间隔走。
- `setConfig` 里 `applyTimer()` 与 `applyPeer()` 并列；改别名即时生效（下一条宣告就带新名）。
- 端口由系统分配，所以重启后端口会变——桌面端按 fingerprint 去重、按 `last_seen` 判在线，
  端口变化不影响识别。

## 自测

`just peer-selftest`：moc + cl 独立编译 `tools/vigorhubpeer_selftest.cpp` +
`src/vigorhubpeer.cpp`，链 Qt6Core / Qt6Network，编译完直接跑，退出码非 0 即失败。

只构造 `VigorHubPeer`，**不构造 `VigorHubRelay`**，所以不读写真实 `awqtui.ini`、不碰用户配置。

本轮结果：**48 条 PASS，fail=0 skip=0**。分段：身份 4、报文形状 10、路由纯函数 8、
真 TCP 15（另 3 条 `[INFO]` 诊断）、真组播 5、起停 6。

覆盖：身份（稳定 / 32 位十六进制 / 与 hub 命名空间不同）、报文形状（平铺而非嵌套 `info`、
`announce:true`、`device_type:aw`）、路由（`/info`、`/snapshot`、查询串、未知路径、非 GET、
provider 缺失）、真 TCP 往返、绑定地址硬门 + 探测夹具 control、真组播接收、起停幂等与重启后可用。

组播接收那一段若绑不上 53317（别的进程占着组播端口）或没有可用组播网卡，
打 `[SKIP]` 并单独计数，不冒充通过。53317 是**共享组**（hub 与 LocalSend 都往这里宣告），
所以必须按自己的指纹认领收到的报文，外来报文只计数——第一版夹具拿「收到的第一个数据报」
当自己的，量到的是别人的身份，5 条全红；本轮 `own=1 foreign=2`。

### 真网络段一律挂空快照

第一版在真起的服务上挂了假快照（`day=20000` / `app="自测"` / 游标 `{"bucket":"b","last_id":3}`）。
**宣告一发出去，同机跑着的真实 hub 就发现并按 60 秒节拍真的来拉**，把假游标并进了它的
`state.json`。使用聚合没脏（`day=20000` 早于 180 天裁剪线，被 `prune_usage` 挡掉），
但游标脏了一条，得停掉 hub 才能清（它在跑时每 60 秒从内存重写盘）。

现在真网络各段一律用空 provider `{"aw":{"app_usage":[],"cursors":[]}}`：
空数组走 hub 的 `merge_usage_full` / `merge_usage` 都是 no-op。
假数据的逐字节断言只留在纯函数 `routeRequest` 段——那里不联网，谁也拉不到。

**教训**：这个自测不是封闭夹具，它往真实局域网里宣告，同机的真实程序会来消费它。
凡是会走到真实管线的探针，先问「除了读数它还写什么」。

### mutant 门

三臂都在源码副本上跑，共享树没动，判定 `GATE_PASS`：

| 臂 | 改动 | 结果 |
| --- | --- | --- |
| control | 无（sha256 与 `src/vigorhubpeer.cpp` 相等） | `fail=0 skip=0 exit=0` |
| mutant-bind | `listen(QHostAddress::Any, 0)` → `LocalHost`，1 行 / 共 274 行 | `fail=2 exit=1`，红在 `listener is bound to Any` 与 `restart still binds Any` |
| mutant-fp | 指纹种子 `aw-qtui\|` → `health-motion\|`，1 行 | `fail=1 exit=1`，红在 `fingerprint differs from hub namespace` |

两个 mutant 都红在**预期的那一条**上，没有误伤别的检查。
门脚本跑的时候要注意：mutant 本来就该退出非 0，`$PSNativeCommandUseErrorActionPreference = $true`
会在读到输出之前就抛异常，把「红在哪一条」这个最关键的证据吞掉——跑 exe 那一段要临时关掉它。

### 构建产物身份

`just build`（Release，`build/`）产出 `awqtui.exe`，2548224 字节。从产物字节里回读：
`aw-qtui|`（UTF-16LE，`QStringLiteral` 存宽字符）在、`health-motion|` 不在，
`/api/health-motion/v1/snapshot` 与 `224.0.0.167`（UTF-8，`QByteArrayLiteral`）都在。
所以新对等代码与正确的指纹命名空间确实进了这份二进制。

> `build-verify/` 里那份 `awqtui.exe` 是 2026-09-23 的旧产物，`CMakeCache.txt` 记的源目录
> 还是仓库搬家前的位置，`just build Release build-verify` 会直接报 CMake 源目录不匹配而失败
> （**just 的包装退出码仍报 0**）。本轮没动它，改用当前路径的 `build/`。
> 认证据只认日志里的 `[5/5] Linking` 行 + 产物 mtime + 字节回读，不认退出码。

桌面端那一半的门与真机证据在 vigorhub 仓库的
`docs/evidence/2026-11-09-aw-peer/`（`cargo test` 75/0，含一条真起 `tiny_http` 走真
`pull_once` 的 AW 快照拉取测试）。

## 本次刻意没做

- **没做 hub 自动发现来反填推送地址**。推送目标仍是显式配置的，避免 silently 改目标；
  需要「零配置推送到任意一台 hub」时再加，那是独立一件事。
- **没动 aw-sync 那条局域网同步**（UDP 广播 46000、设备注册表、配对）。那是本应用
  自己的多端同步，和 VigorHub 协议无关，两条路各走各的端口。
- **没 bump 版本号**（`CMakeLists.txt` 仍 0.1.43），**也没装机**。运行中的仍是
  `C:\workshop\aw-qtui-0.1.43\awqtui.exe`，不含 `VigorHubPeer`；桌面端跑的也仍是旧构建。
  装机要先点头，而且版本号必须跟着 bump：新旧内部版本相同时单实例仲裁走同版本分支，
  交接会无声失败（justfile `bump-version` 的注释写了原因）。
- **没在真·第二台 AW 主机上验过 `sourceLabel`**。口子留了，默认值 `desktop` 也钉了提示，
  但「两台主机各填不同标识、时长不相覆盖」这一格只有推理，没有实测。
