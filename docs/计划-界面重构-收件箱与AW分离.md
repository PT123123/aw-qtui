# 界面重构计划：收件箱 与 ActivityWatch 分离

> 状态：计划稿（未改代码）。目标：消除"两个产品挤在一起"的观感，让界面干净、有层次。
> 依据：`_shots/*.png` 截图 + `src/theme.h` / `src/mainwindow.cpp` / `src/widgets.cpp`。

## 1. 诊断：丑在哪儿

| # | 问题 | 证据 |
|---|------|------|
| 1 | **信息架构混排**：两类产品塞进同一条侧栏 | 侧栏两个可折叠分组：「收件箱」（收件箱+局域网同步）与「ACTIVITYWATCH」（Activity/Timeline/标签 Day/统计） |
| 2 | **视觉语言打架**：笔记应用 vs 监控仪表盘 | 收件箱=MoeMemos 卡片流（10px 圆角卡/相对时间/emoji/FAB/Markdown），AW=密集数据页（图表/筛选/工具栏/时间轴），共用一套全局 QSS，谁也不像谁 |
| 3 | **身份信号错位** | 窗口标题 "aw-qtui — ActivityWatch 客户端"，但默认落在收件箱；导航"ACTIVITYWATCH"全大写英文 + "收件箱"中文混排；品牌名本身是缝合名 |
| 4 | **交互密度冲突** | 收件箱=内容流（滚动友好），AW=控制密集（筛选/拖拽缩放/工具栏） |

## 2. 三个方向

| 方案 | 做法 | 优点 | 代价 | 适用 |
|---|---|---|---|---|
| **A 单窗口 + 顶层域切换（推荐）** | 保留一个进程，壳层改为「收件箱 / ActivityWatch」两个顶层域，各带子导航 + 独立强调色 + 统一页头 | 改动集中在壳层；全局热键/服务端/本地存储全部复用；同一时刻只呈现一个域，彻底消除混排感 | 需改导航与页头组件，回归热键/缩放 | 匹配"结构不干净"这一根因 |
| B 拆成两个 exe | 收件箱与 AW 各独立成 app | 物理隔离，各自完全自洽 | 壳层/配置/托盘/热键/构建/打包全翻倍 | 想要两个真正独立产品时才值得 |
| C 维持混排只统一视觉 | 保持现状导航，仅统一色板/圆角/间距 | 改动最小 | 治标不治本，"挤一个导航"的观感仍在 | 完全拒绝结构改动时的兜底 |

**推荐 A**，其中"统一设计令牌"（C 的内核）是 A 的必经子步骤。

## 3. 方案 A 落地步骤（对应文件）

### P0 · 设计令牌统一（`src/theme.h`）
- 散落 `#hex` 收敛为 token：`bg/bg-elev/border/fg/fg-muted/radius/spacing/字号阶梯`。
- 引入**域强调色**：收件箱 = 现有蓝 `#4c8bf5`；ActivityWatch = 新分配（青绿或紫）。只用于选中项/页头/链接，占比低，避免变成"两种主题"。

### P1 · 壳层改造（`src/mainwindow.cpp` / `.h`）
- 去掉两个可折叠分组，改为**顶层域选择**（侧栏顶部两个大入口，或顶部 segment）。
- 每个域独立的页头组件（标题 + 日期/筛选区）；页面堆栈按域分组切换。
- 快捷键保留 1–6 全局映射（或按域重排）；`Ctrl+滚轮` 缩放逻辑不动。
- 窗口标题/品牌改为中性 "aw·qtui"，按当前域显示副标题。

### P2 · 页面级对齐
- 收件箱：保留 MoeMemos 卡片语言，卡片圆角/边框/间距对齐令牌系统。
- AW 四页：抽出共用 `PageHeader`（日期导航 + 筛选 + 刷新），让 Activity/Timeline/Day/Stats 长得像一家人。
- FAB 只出现在收件箱域；AW 域用工具栏按钮。

### P3 · 验收
- 每个域内部完全自洽；切换域如同切换 app；基础令牌一致，仍是一个产品。

## 4. 风险
- 壳层改动影响热键/缩放，需回归 1–6 快捷键与 `Ctrl+滚轮`。
- 域强调色必须克制，否则又变成"两套主题"。
